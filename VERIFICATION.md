- .NET 10.0.401 SDK; Avalonia 11.3.22; Microsoft.Data.Sqlite 10.0.12.
- `dotnet test Fitlog.slnx`: **17 passed, 0 failed**.
- Release publication succeeded as a self-contained Windows x64 executable.
- Launched the published executable; process remained running and exposed a native window titled `fitlog — Your fitness, day by day`.
- Replaced the earlier executable after a graceful app shutdown, kept its previous build, copied the closed database to the local Backups folder, and relaunched the updated app successfully. Installed and staged executable hashes matched.

## Tested behavior

- Database persistence across repository reopening, Unicode notes, same-date weight updates, and deleting only the selected record.
- Full backup round trip, merging without removing unrelated records, repeated imports, and rejecting invalid imports without partial writes.
- Numeric validation, week boundaries, gym streaks, and sparse weight history calculations.
- UI interactions for saving a daily check-in, weight, measurements, and a goal.
- Persistent appearance and unit preferences, including pounds-to-kilograms conversion through the weight editor.
- Rendering all ten navigation pages, plus compact-width and light-theme screenshots.
- Local-time rollover across midnight and month boundaries through an injected TimeProvider, without reopening the app.
- Distinct training/rest/missed attendance and partial workout/diet percentages; version 1 backup compatibility without inventing rest days.
- Custom workout routine creation, adding/removing exercises, editing, and independence from daily attendance.
- Album-linked multi-photo insertion, two-image comparison, opening a photo, and zoom changes.
- Arabic preference persistence, RTL navigation, all ten pages in Arabic, and focused input styling.
- Main window configured without system decorations; embedded logo PNG and application-owned window controls.

Rendered screenshots are generated by Avalonia Headless with the Skia renderer in `artifacts/screenshots/`. Dashboard, calendar, weight, settings, compact layout, and daily editor were visually inspected against the supplied design direction. Screenshot data is synthetic and isolated from the user's database. The app starts empty.

## Verification limits

Windows Computer Use reported `Computer Use native pipe is unavailable ... (os error 2)` during the initial build. Native drag/resize/window controls and operating-system file-picker dialogs were not automated. UI interaction tests use Avalonia Headless. Photo batch persistence was tested through the same editor/save path with fixture bytes rather than an OS file picker. Photo comparison screenshots use the generated logo as a test fixture; no personal photos are inserted. macOS and Linux were not tested.
